# Toki Pona Icon Pack

An Android icon pack made of **sitelen pona** glyphs, drawn with the
[nasin-nanpa](https://github.com/ETBCOR/nasin-nanpa) font by jan Itan.

Every app gets a toki pona word or compound: the phone is *ilo toki*, the clock
*ilo tenpo*, the calendar *lipu tenpo* (tenpo inside lipu), Bluesky *waso laso*…
Apps without a glyph of their own get the one of their **category**: banks *tomo mani*,
email *lipu*, browsers *linluwi*, music *kalama musi*, and so on (~1,500 apps covered).

Available in English, Español, Français, Italiano and Esperanto.

## Features

- **Icon pack** for the usual launchers (Niagara, Nova, Lawnchair, Smart Launcher, ADW…).
- **Every nasin-nanpa word** (and its variants) as a standalone icon, plus ~3,000
  ready-made **compounds** (*ilo …*, *tomo …*, *lipu …*, …) to pick by hand in your
  launcher.
- **Glyph editor**: type `toki pona`, `ilo tenpo` or `poki+sewi1` and see the glyph
  instantly. Pick colours and stroke weight, export to **SVG** or **PNG**.
- **Shortcuts**: put any glyph on any app as a home-screen shortcut. Works with every
  launcher and needs nothing else.
- **Apps without an icon**: the app finds your installed apps that the pack doesn’t
  cover yet, suggests a glyph for each one and turns it into a shortcut in one tap.
- **Icon picker** for launchers that support it (Nova, ADW…), including your saved glyphs.

## Using the icon pack

Open your launcher settings → Appearance → Icon pack → **Toki Pona Icon Pack**.
For a single app, long-press it → edit → icon → Toki Pona Icon Pack, and choose any
word or compound.

## Writing compounds

| You type | Result |
|---|---|
| `toki` | a single word |
| `sewi1` or `sewi:1` | variant 1 of the word |
| `ilo tenpo` | automatic: if the first word has a hollow (*tomo, lipu, toki, sona, mani, jan, poki…*) the second goes **inside** it; otherwise they are **stacked**, first word at the bottom |
| `jan^pona` | force stacking |
| `pilin+pona` | force nesting |

## Building

Open the project in Android Studio and press Run. All generated icons are committed,
so you don’t need Python to build.

- minSdk 26 · Kotlin · Jetpack Compose (Material 3)

## For the curious: tinkering with the pack

Everything below is optional. The app on the store never depends on it.

### Regenerating the icons

The vector drawables, `appfilter.xml` and `drawable.xml` are generated by
`tools/generate_icons.py` from the font bundled in `app/src/main/res/font/`. It uses
HarfBuzz, so compounds are composed exactly as the font does it.

```sh
python3 -m venv ~/.venvs/tokipona-icons
~/.venvs/tokipona-icons/bin/pip install -r tools/requirements.txt
~/.venvs/tokipona-icons/bin/python -I tools/generate_icons.py
```

- `tools/categories.json`: one generic glyph per app **category** (banking, email,
  messaging, video, music, maps…) and the packages that belong to it.
- `tools/apps.json`: **specific** glyphs for specific apps (`components` =
  `package/Activity`). They always win over the category glyph.
- `tools/known_components.json`: exact `package/Activity` names for the packages in
  `categories.json`. Rebuild it after adding packages with
  `tools/generate_icons.py --refresh-components`, which extracts only those identifiers
  from the community-maintained [Arcticons](https://github.com/Arcticons-Team/Arcticons)
  `appfilter.xml` (no icons are taken from it).
- At the top of the script: style (`FILL`, `OUTLINE`, `THIN` for stroke weight) and
  `COMBO_HEADS` (the words used to generate the automatic compounds).

Why categories and not “every bank gets the money icon” automatically? A launcher can
inspect your apps at runtime, but an icon pack is a static `app → icon` table, so the
category lists are written ahead of time. The app’s *Apps without an icon* screen does the
runtime guessing for everything else.

### Debug builds: assign glyphs from your phone

Debug builds (the ones you get from Android Studio) show extra developer tools:
**Assign to app…** and a list of pending assignments. To bake them into the pack:

1. In the app, type a glyph → **Assign to app…** (or just **Save** it).
2. With the phone connected over ADB:
   ```sh
   tools/sync_from_phone.sh               # read from the phone, regenerate, build, install
   tools/sync_from_phone.sh --no-install  # only regenerate (then Run in Android Studio)
   ```
   With several ADB connections, pick one with `ANDROID_SERIAL=…`.
3. Re-apply the icon pack in your launcher so it refreshes the icons.

What is read from the phone is stored in `tools/apps_device.json` (git-ignored).
